# planner-comments — 기획자용 한국어 주석

화면 코드 파일에 기획자가 읽고 "이 부분이 왜 있는지" 알 수 있는 한국어 주석을 단다.

대상 파일: $ARGUMENTS

## 작업 순서

1. **대상 확인**
   - 위 "대상 파일"에 적힌 파일에만 주석을 단다.
   - 비어 있으면 어느 파일에 달지 사용자에게 먼저 묻는다. 직접 찾아서 고르지 않는다.
2. **원본 보관**
   - 수정하기 전에 각 대상 파일을 스크래치패드(없으면 임시 폴더)에 복사해 둔다. 마지막 확인 단계에서 비교할 때 쓴다.
3. **PRD 읽기**
   - `docs/PRD.md`를 읽는다.
   - 그 화면이 4장 "화면별 기능"의 어느 화면인지, 어떤 유저 스토리(US1~US5)와 판정 규칙(1~7번)에 해당하는지, 어떤 오류 문구가 쓰이는지 파악한다.
4. **주석 넣기** (먼저 보여주지 않고 파일에 바로 넣는다)
   - **파일 요약 1개:** 파일 맨 위에 넣는다. 화면 이름, 라우트, 이 화면이 하는 일, 관련 유저 스토리를 3~5줄로 쓴다.
   - **덩어리별 주석:** 헤더, 카드, 필터, 입력란, 하단 버튼처럼 화면의 영역이 시작되는 바로 위에 1~2줄로 쓴다. 무엇을 보여주는지, 언제 바뀌는지, 관련 US나 판정 규칙 번호를 적는다.
   - 줄마다 달지 않는다. 기획자가 알아야 할 동작(조건부 표시, 버튼 비활성 조건, 화면 이동, 오류 문구)이 있는 곳에만 단다.
5. **확인과 보고:** 아래 "끝났는지 확인"을 따른다.

## 결과물 형태

- 결과물은 원래 화면 파일 안의 주석뿐이다. 요약 문서 같은 별도 파일은 만들지 않는다.
- 주석 문법은 파일 형식에 맞춘다.
  - JS/TS 코드 부분: `// ...`
  - 파일 맨 위 요약: `/** ... */`
  - JSX(화면 마크업) 안: `{/* ... */}`
- 말투는 해요체로 쓴다.

예시:

```tsx
/**
 * 요금제 목록 화면 (/plans)
 * 요금제 4개를 카드로 보여주고, 고객이 데이터량·소진 후 속도·매달 내는 금액을 비교해 고르게 해요.
 * 관련: US1, US2, US3, US4
 */

{/* 요금제 카드: 할인이 있는 요금제(p03)만 '25개월째부터 ○원' 줄을 보여줘요. (US4, 판정 규칙 4) */}
```

## 꼭 지킬 것

- **코드는 절대 바꾸지 않는다.**
  - 주석은 새 줄로만 추가한다. 기존 줄의 끝에 덧붙이지 않는다.
  - 코드, 들여쓰기, 변수 이름, 기존 주석은 그대로 둔다.
  - 버그나 PRD와 다른 부분을 발견해도 고치지 않는다. 마지막 보고에서 알려만 준다.
- **개발 용어를 그대로 쓰지 않는다.** 기획자가 쓰는 말로 바꿔 쓴다.
  - `useState` → "입력값/선택값을 기억해요"
  - `props` → "앞 화면에서 넘겨받은 값"
  - 렌더링 → "화면에 보여줘요"
  - `disabled` → "버튼이 눌리지 않아요"
  - `router.push` → "○○ 화면으로 이동해요"
  - 화면 이름과 컴포넌트 이름은 PRD.md 표기(예: 요금제 상세, Card/Plan, BottomCTA)를 따른다.
- **고객 개인정보를 쓰지 않는다.** 실제 이름이나 휴대폰 번호 같은 고객 정보를 주석 예시에 넣지 않는다. 조직 규칙이다.

## 끝났는지 확인

1. **코드 변경 0줄**
   - 보관한 원본과 수정본을 비교한다. 예: `git diff --no-index <원본> <수정본>`
   - 통과 조건: 삭제되거나 바뀐 줄이 하나도 없고, 추가된 줄은 모두 주석 줄이어야 한다.
   - 주석이 아닌 줄이 바뀌었으면 그 변경을 되돌리고 다시 확인한다.
2. **보고**: 끝나면 사용자에게 다음 두 가지를 알려 준다.
   - 파일별로 단 주석 수 (예: `app/plans/page.tsx` — 요약 1, 덩어리 6)
   - 발견 사항: 주석을 달다가 본 PRD와 다른 동작, 버그로 의심되는 부분, PRD에 "확인 필요"로 남아 있어 주석에 그렇게 적은 부분. 없으면 "없음"이라고 쓴다.
